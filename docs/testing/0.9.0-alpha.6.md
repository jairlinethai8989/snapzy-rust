# SnapZy Rust Preview 0.9.0-alpha.6

Local portable tester candidate. No Git push or public release before approval.
Functional parity comes first; broad .NET visual/editor parity is not included.

## What Changed

- Compared against Neo Snap .NET 0.1.20 at commit `222df09`, rather than assuming
  the Rust click-first detector was equivalent.
- Hover for a colored frame, review it, then click-release once inside to start
  Automatic/Manual scrolling. Detection keeps the overlay visible and does not
  activate it or send wheel input. A retained valid frame stays visible while
  it is refined; stale generations and obsolete pressed frames cannot start.
- Ported the .NET persistent-grid/broad-colored-header detector. Frozen rows
  remain within the selected sheet bounds. Original image pixels are unchanged.
- Native descendants and UI Automation are resolved from the source HWND, not
  the overlay covering the pointer. UIA prefers the smallest vertical scrolling
  pane, then a Document. A client-window fallback is explicitly labeled with an
  amber outline; it is not confirmation of scrollability.
- A real WPF provider regression exposed a second issue: a cold root lookup
  took about 601 ms, exceeding the previous 250 ms subtree budget before its
  scrolling child was visited. The subtree budget is now 1500 ms, still bounded
  by 250 nodes/depth 20 and the existing four-second helper-process hard limit.
- Escape cancels pending probes without waiting for a stalled provider.

## Verification

- Windows x64 unit tests: 127 passed, zero failed. Some OCR/network and local
  image checks are opt-in; the unit total alone does not imply they were run.
- Explicit opt-in sheet test on the tester's original Lark screenshot passed:
  viewport `(0, 3, 1910, 746)`. This verifies static bounds recognition only.
- Native-message scrolling regression passed manual/automatic frozen-header and
  footer exact pixels, PNG/clipboard parity, hover before clicking, no overlay
  activation, click-release confirmation, pending-detection Escape, two stalled
  probes/retry/labeled fallback, Pause/Resume and Stop/Cancel.
- Automatic regression includes 900 ms delayed rendering, focus-only and
  untitled-cover safety pauses, explicit resume, no-motion partial completion
  and no late input after cancellation.
- The independent WPF ScrollViewer test passed with another test-owned window
  covering the pointer. It selected viewport `(232, 155, 436, 413)` through the
  source HWND and did not change the source's scroll offset.
- Alpha 5 failed the new hover-before-click test. The WPF test failed before
  the search-budget correction and passed afterwards (regression RED/GREEN).

Observed window-readiness timings in the final native fixture were 270.14 ms
for the launcher, 161.24 ms for area selection and 74.00 ms for area preview.
These are not complete-paint timings or a .NET comparison. The WPF root-provider
test took 2652.71 ms including helper startup; sheet recognition uses a separate
image path and does not wait for that provider.

An earlier smoke attempt run alongside the WPF covering-window fixture failed
the stalled-detector assertion. The isolated rerun above passed; run these
desktop fixture scripts separately to avoid cross-test covering/focus effects.

These checks use test-owned native windows and native messages. They are not
physical mouse/keyboard, hardware wheel, actual Lark/Excel, mixed-DPI or
paint-completion latency tests. Sheet detection is heuristic: a table without
the recognized grid/header may use accessibility or the labeled window fallback.
Scrolling retains the existing 32 MiB source limit and does not guess bad joins.

## ทดสอบรุ่นนี้

1. ปิด Rust Preview เดิมจาก Tray แตก ZIP Alpha 6 ไปโฟลเดอร์ใหม่ ไม่ทับรุ่นเก่า
   เปิด `SnapZy-Rust.exe` และตรวจเวอร์ชัน `0.9.0-alpha.6` ไม่ต้องติดตั้ง .NET
2. เปิด Lark แผ่นงานที่เคยจับได้และแผ่นที่เคยมีปัญหา เลือก Automatic แล้ว Scrolling
3. วางเมาส์เหนือกลางตาราง **ยังไม่คลิก** รอกรอบสี ตรวจว่าครอบตารางและแถวตรึงถูกต้อง
   หน้าจอต้องไม่ซ่อน/เปิดซ้ำ และตารางต้องยังไม่เลื่อน
4. กรอบสีน้ำเงินมาจากตัวตรวจตาราง/แถบเลื่อน/ระบบการเข้าถึง ถ้าเป็นกรอบสีเหลือง
   พร้อมข้อความกรอบหน้าต่าง ให้ตรวจขอบเขตก่อน เพราะเป็นกรอบสำรอง ไม่ยืนยันว่าเลื่อนได้
5. คลิกและปล่อยภายในกรอบหนึ่งครั้ง ต้องเริ่มจับภาพ ไม่ต้องกดเริ่มซ้ำ
   ตรวจแถวหาย/ซ้ำ รอยต่อ แถวตรึง และแถบเลื่อนล่าง แล้ว Save PNG / Copy
6. ลอง Pause/Resume และ Stop ลอง Manual ด้วยการหมุนล้อลงทีละช่วงพร้อมส่วนซ้อนทับ
7. เปิด Scrolling อีกครั้ง กด Esc ทั้งระหว่างกำลังตรวจและหลังมีกรอบ ต้องยกเลิกได้
   หากไม่พบพื้นที่ ให้ย้ายเมาส์ไปจุดอื่นเพื่อลองใหม่ ไม่ใช้การลากกรอบ
8. ทดสอบ Excel และจอ 125-200%/หลายจอ หากยังผิด ส่งภาพกรอบและ log ล่าสุดใน
   `%LOCALAPPDATA%\SnapZyRustPreview\Logs` พร้อมชื่อแผ่นงานและโหมด Auto/Manual

## English Quick Check

Exit the old Rust preview, extract Alpha 6 into a new folder, and run its EXE.
Choose Scrolling, hover over the intended content without clicking, review the
colored bounds, then click-release inside once. Escape must cancel while either
checking or ready. Amber means a window fallback needing review. Test both Lark
sheets, Excel, Auto/Manual, frozen rows, joins, PNG/clipboard and physical input.
