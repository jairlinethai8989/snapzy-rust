# SnapZy Rust Preview 0.2.0-alpha.2 Verification

Date: 2026-10-09, Asia/Bangkok. Local tester ZIP only; not pushed or published.
The .NET SnapZy and Neo Snap programs are unchanged.

## Report and Diagnosis

The tester reported continuous editor flicker and jagged dragging strokes that
became smooth only on release. The previous editor invalidated the entire window
on every mouse move, filled the visible background and then drew the image. Draft
strokes used integer GDI lines, while completed strokes used antialiased tiny-skia.
Fractional canvas origins also caused a half-pixel mapping mismatch.

The original alpha.1 failed the native line regression: 208 interior image pixels
changed on release and no antialiased draft pixels were found. Separate failing
unit tests covered idle redraw requests, draft rendering and offscreen painting.

## Fix

- Share a reusable offscreen display DIB across serialized editor paints, capped
  at 64 MiB. Compose first and BitBlt to the target once; release native objects
  on replacement/shutdown. Keep captured sources and document caches independent.
- Ignore idle, unchanged and crop-confirmation hover updates.
- Rasterize draft strokes through the same antialiased stroke helper as export.
  Allocate only the clipped visible stroke tile in display coordinates.
- Align the canvas origin to display pixels. Source image dimensions and export
  pixels are not reduced or resampled by this fix.

## Validation

- `cargo test --locked`: 28 passed, zero failed.
- Formatting check, Release build and tracked diff whitespace checks passed.
- Clippy passed with warnings denied except the four style categories documented
  in the alpha.1 verification note; this is not an unqualified strict-lint pass.
- Native `tools/smoke-test.ps1 -EditorChecks -PaintChecks` passed. It compares
  live and finished interior pixels for pen, line, arrow and rectangle at 100%:
  zero changed pixels, with partial-coverage antialiased edges present.
- Repeated 30 window resizes: native GDI resource delta zero.
- Retained capture, original PNG, crop/Undo/Redo, style, EN/TH, Help and actual
  Windows clipboard image checks passed. Synthetic screenshots were inspected.
- Unit tests are the deterministic guard for ignoring idle mouse movements;
  the native update-region probe is supplementary and can race the message loop.

Native evidence: `artifacts/smoke-94888e1145aa4a2bbd4f44848eacdb06`.
Both tested monitors are 96 DPI. High/mixed DPI, chat apps, physical hotkeys and
perceived flicker/smoothness on the tester's PC still require hands-on checks.
At scaled display sizes, live strokes are antialiased at display resolution while
finished/exported images retain source-resolution rendering; edge pixels can
therefore differ slightly. No interpolation or automatic reshaping is added.

## Responsiveness

Three alternating samples per build, same machine and synthetic capture fixture.
Baseline is the previous 0.2.0-alpha.1 editor candidate, not the .NET application.

| Metric (ms) | Alpha.1 Median / Slowest | Alpha.2 Median / Slowest |
| --- | --- | --- |
| Launcher window detection | 284.07 / 412.97 | 238.31 / 243.30 |
| Selection window detection | 162.49 / 175.88 | 162.40 / 185.17 |
| Preview window detection | 56.98 / 69.21 | 45.84 / 85.07 |
| Instrumented launcher ready | 50.576 / 52.234 | 46.488 / 48.842 |
| Instrumented selection first paint | 178.603 / 187.853 | 173.150 / 189.909 |
| Instrumented preview first paint | 130.978 / 134.544 | 110.555 / 151.821 |

Peak working-set medians were 101720064 / 103456768 bytes respectively.
Measurements vary and three samples cannot establish a general speed advantage.
Window detection is not paint completion; instrumented first paint measures the
application WM_PAINT completion, not compositor-visible screen completion.
These checks show no obvious median capture slowdown in this fixture, not a
latency guarantee or a full interactive-drag benchmark.

Performance evidence: `artifacts/comparison-e83f44c3e602421681d6c26086ad98fa`.

## Tester Checks

1. Exit the previous Rust Preview from its tray menu, extract the new ZIP, and
   run `SnapZy-Rust.exe`. No installer or .NET runtime is required.
2. Open a capture. Hover and move the pointer without drawing; check for flicker.
3. Slowly draw diagonal pen/line/arrow/rectangle strokes and compare their edges
   while dragging and after release. Also check a larger image fitted to screen.
4. Move an object, crop/cancel, resize and switch monitors. Confirm Copy/PNG,
   Undo/Redo and capture response are still satisfactory before approving push.
