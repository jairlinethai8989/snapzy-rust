# SnapZy Rust Preview 0.9.0-alpha.7

Local portable candidate only; no Git push before tester approval.

## Fix

The non-activating scrolling controller leaves focus on the source application.
Alpha 6 removed its selection Escape registration when capture began, leaving
only a local controller key handler. That handler could not receive Lark's keys
and would discard the session if it did receive them.

User-approved behavior in Alpha 7:

- Escape during selection/detection still cancels.
- Escape during capture or pause acts as Stop: open accepted partial pixels in
  the editor. Cancel still discards. Without an accepted initial image, report
  that no stable frame was captured rather than invent a result.
- Reserve Escape only while selecting/capturing and release on teardown. The
  existing polling timer checks key state if another owner prevents registration.
- Global Escape, controller Escape and a focused controller-button Escape all
  share the existing Stop action. No reactivation of the controller is needed.

The tester subsequently confirmed Lark scrolling works. Read-only observation
saw the accepted height grow beyond two steps, with responsive controls. The
earlier stop could not be attributed conclusively; no settling, overlap or wheel
threshold was relaxed as a speculative fix.

## English Check

Exit the old Rust preview, extract Alpha 7 into a new folder and run its EXE.
Start scrolling on Lark. Press Escape with Lark focused: scrolling must stop and
the accepted partial image must open. Repeat while paused and in Manual mode.
Cancel still discards, selection Escape still cancels, and Escape must be released
after the controller closes. Hardware keyboard delivery on Lark remains a tester
acceptance check, distinct from OS-injected keys on test-owned windows.
