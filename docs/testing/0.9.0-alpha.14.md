## Changes

- Single-file `.snapzy` ZIP/JSON/PNG projects preserve original pixels, image
  sharing, editable annotations/layers/curves, Thai/English glyph coverage,
  shadows/outlines, opacity, crop and expanded source clipping.
- Open creates a separate editor; selection and Undo/Redo start fresh.
- Editor folder icon: Open. Save icon: Save / Save As. Launcher: Open project.
  Ctrl+O / Ctrl+S / Ctrl+Shift+S outside text/numeric entry dialogs.
- Background save with exclusive sibling temporary file, flush/sync and Windows
  replacement. Failed writes leave prior destination intact.
- Project-saved revision is independent of Copy / PNG. New captures are unsaved
  projects even after PNG export; close offers Save / Discard / Cancel.
- Exit stages individual decisions; cancellation/failure does not discard the
  remaining editors. Saves are serialized to bound archive encoding buffers.
- Warn before first Save and every Save As: original data remains beneath blur
  and covering shapes. This is not encrypted storage or secure redaction.
- Bounds on archive/JSON/source pixels/masks/objects/points. Unknown schema,
  invalid asset hashes, unsafe paths, duplicate entries/IDs and malformed
  local ZIP metadata are rejected without extraction.

  successfully, but this is not evidence that its native scenarios pass.

Schema 1 uses a strict ZIP profile: stored/deflate entries, no ZIP64,
archive comments, local extra fields, encryption or data descriptors. Projects
are generated by SnapZy, not intended for generic ZIP-editor modification.
SHA-256 checks detect corruption; they do not authenticate a project author.
