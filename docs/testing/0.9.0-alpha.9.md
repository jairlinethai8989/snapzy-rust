# SnapZy Rust Preview 0.9.0-alpha.9

Date: 2026-10-11 (Asia/Bangkok). Local portable candidate only.
No Git push, public release or .NET changes.

## Fix Scope

Stop/Escape disables wheel input immediately, then samples the final pending
scroll for up to two seconds. It still requires stable frames, confident overlap,
an unchanged safe target and the existing image budget. Stable unchanged old
frames do not prematurely complete an outstanding wheel. Repeated Stop does
not reset the finishing deadline. Cancel discards the finishing job with no
late preview. Localized finishing and unconfirmed-partial notices are included.
The deadline bounds sampling, not all subsequent validation/PNG/preview work.

## Root Cause And RED

User evidence shows a trailing gap: stitched output ends at row 22 while the
live Lark viewport already shows lower rows. Automatic capture accepted a
frame, sent the next wheel, then Stop broke the worker before sampling it.

Native Alpha 8 reproduction:
`artifacts/smoke-1d1fd324f1714961b95cbe77374cdc95/partial-results.json`.
The source received exactly one wheel and advanced its logical offset by 60,
with a 900 ms delayed paint pending. Stop returned `223 x 400 px` instead of
the required `223 x 460 px`. This is the expected failing test, not a pass.

## Verification

Final staged native regression passed:
`artifacts/smoke-70b5a883e3494bacad5dec15449377fc/results.json`.
Executable version and SHA-256 match the candidate below. This run used
guarded OS clicks/Escape on test-owned windows, not MessageOnly.

- Stop and Escape during a 900 ms delayed render both produced exactly
  `223 x 460 px`, including every body/footer pixel, with exactly one wheel.
  Stop-to-preview was 1232.404 ms and Escape-to-preview 1296.949 ms.
- Cancel during finishing produced no late preview or additional wheel.
- Repeated Stop did not restart the deadline. An unchanged old frame stayed
  partial, with the explicit final-frame timeout notice at 2368.449 ms.
  This observer value includes polling/UI/preview work beyond the sampling
  deadline; it is not a promise of exactly two seconds to preview.
- A covered final source was rejected, preserving the accepted partial image
  with a target-change notice and no extra wheel. Unsaved-close confirmation
  completed through the normal confirmation flow.
- Existing manual/automatic scrolling, exact frozen header/footer pixels,
  Stop from Pause, Cancel, PNG/clipboard parity, hover/click confirmation,
  focus/untitled-cover safety pauses, explicit Resume, no-motion completion,
  hotkey registration/release and OS Escape hotkey-conflict fallback passed.
- Basic native EN/TH launcher, region/window/desktop capture, source pixel
  checks, Unicode filename, hotkey conflict/success and exit also passed.
  Observer launcher/selection/preview times were 300.30/212.34/43.85 ms.
  These are single window-detection observations, not complete paint/input
  latency or a before/after performance comparison. Peak working set was
  107,307,008 bytes; one run does not establish leak freedom.

This fixture is not live Lark, physical-key/wheel delivery or mixed-DPI

## Tester Steps

1. Exit the old preview via Tray, extract Alpha 9 to a new folder and verify
   `0.9.0-alpha.9` in the running program.
2. Use the same Lark sheet, choose automatic scrolling and confirm the frame.
3. Press Escape immediately after the table advances. While finishing, no
   additional scroll should occur. Compare the final visible row with PNG.
4. Repeat with Stop and from Pause. Repeated Stop must not keep extending the
   wait. Cancel during finishing must not produce a preview afterwards.
5. Try Manual, Excel, EN/TH and PNG/clipboard parity. A moved/covered/unstable
   source must retain only validated content with an explanation.
