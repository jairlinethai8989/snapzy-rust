# SnapZy Rust Preview 0.5.0-alpha.1 Verification

Date: 2026-10-09, Asia/Bangkok. Independent local portable candidate for
text backgrounds and speech bubbles after the tester confirmed alpha.2 manual
scrolling works. No .NET changes, installer, commit, push, tag or public release.

## Changes

- Text backgrounds are transparent by default. Solid fill has its own color
  swatch, initially white; disabling it remembers the color.
- Rounded speech bubbles reuse native multiline Thai/English text editing,
  side wrapping and corner font resizing. The text-mask frame has six handles;
  bubble padding extends 8 source pixels outside that frame.
- Drag the circular tail-tip handle in Select. The base attaches to the nearest
  body edge. A tip inside the body hides the tail. Moving the bubble moves its
  tail; resizing preserves its offset from the text origin.
- Bubble border width is independent of font size. Initial annotation color is
  red, stroke 5 px, font 24 px. No rich text, shadows, opacity or text outlines.
- Fill/tail edits share existing glyph masks and are reversible. Background and
  outline paint before glyphs through the current bounded composition worker.
- Contextual controls and EN/TH Help/tooltips describe the new operations.
- Fixed a native regression where Undo restored border pixels but the border
  field still displayed the previous thickness. Refresh now reflects the
  selected object's actual style, preventing subsequent style edits using it.
- Drag feedback is geometry-only, like the text-frame preview. A regression
  test first failed because a filled draft painted alpha 255 over cached text;
  its body now stays transparent during the drag. Final fill/text update on
  release. No glyph rerasterization or full-frame composition is added per move.

`artifacts/smoke-5ea1ce79b25a4b0284e173c4558238a2` before its fix.

`artifacts/smoke-7403c8d762d24f8382c3d44dc93815bd` before the version bump.

Two harness issues were retained rather than treated as product fixes: undoing
the fixture back to empty must save that reset before closing, otherwise the
expected unsaved-work prompt appears. Also, a posted tool change must finish
before directly setting the new checkbox state; an early full-suite run
(`smoke-b7b4a0fd5dd248f293b103871d0a9295`) created already-filled text and then
incorrectly expected a fill Undo. The transparent PNG itself exposed this.
The fixture now drains the reset via export and synchronously selects Text
before setting its checkbox. A related direct-numeric-write race in
`smoke-2aa100df07ec47c888d3387acb903a9c` was exposed by unchanged text-size PNGs:
the queued selection refreshed the field after the test had written its value.
The parameter helper now exports the preceding selection before writing the
field. PNG equality assertions remain unchanged; this is fixture ordering,
not a claimed fix to user typing or a relaxed rendering check.

## Tester Checklist

1. Export old work and exit Rust Preview through Tray. Extract the new ZIP into
   its own folder and run SnapZy-Rust.exe. Check 0.5.0-alpha.1 on the launcher.
2. Capture a region and add Text. It should be transparent initially. Enable
   Text background, choose a color separate from the red text, disable it and
   re-enable it. Check the color is remembered. Repeat with an existing object.
3. Add Speech bubble (the speech-bubble icon after T). Enter Thai and English
   over several lines. Double-click inside its text to edit later. Check edits
   preserve background, border and tail.
4. Choose Select, click the bubble and drag the circular tail-tip handle to all
   four sides. Move the bubble. Drag text-frame sides to reflow, and corners to
   scale its font. Border px must not change the font size.
5. Undo/Redo each change. Try Esc during tail/resize/move dragging, then a new
   gesture. Check the visible border field after Undo matches the actual border.
6. Save PNG and Copy into a real chat application. Confirm original dimensions,
   sharp text and no selection handles. Crop across the bubble/tail then Undo.
7. Recheck manual Lark scrolling on both previously good/problematic sheets,
   stopping and cancelling several times. This is not automatic scrolling.
8. Try compact windows, 125-200% and mixed-DPI monitors, physical Thai IME and
   physical hotkeys. These cannot be inferred from synthetic native fixtures.

## Known Limits

This remains a portable alpha, not a replacement for the feature-complete .NET
apps. No automatic scrolling, layers, multi-image canvas, OCR, video, editable
project save or installer yet. Export PNG before closing. Existing 32 MiB
aggregate source, 256 MiB composition and glyph/history limits remain.
Manual scrolling uses conservative stable/overlap checks and can stop with a
partial result. Actual Lark joins and chat paste still need hands-on validation.
The alpha.2 optional OS-wheel injection probe remains unresolved; normal native
ScrollChecks do not claim hardware/OS-wheel delivery. Both physical manual
scrolling feedback and automated fixture scope are recorded separately.
