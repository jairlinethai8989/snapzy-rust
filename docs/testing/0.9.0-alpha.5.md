# SnapZy Rust Preview 0.9.0-alpha.5 Tester Report

Local candidate only. No Git push or public release until tester approval.

## Subsequent Tester Feedback

The tester reported that Alpha 5 still could not select the Lark capture area.
Its native-message fixture pass did not establish real Lark compatibility.
Superseded by the Alpha 6 .NET-style hover/frame/click candidate; use
[the current instructions](0.9.0-alpha.6.md) instead of this historical flow.

## Fixes

- Scroll selection now captures the mouse on button-down and starts detection
  only after button-up. Previously the overlay disappeared while the selection
  click was still held, splitting one physical click between two windows.
- Pointer movement in scroll-selection mode no longer repaints the full overlay.
- UI Automation runs in one hidden helper process, limited to four seconds.
  Timeout and cancellation kill and reap the helper before the next request.
  A Windows kill-on-close job also prevents it surviving a main-app exit.
- A timed-out query restores the overlay with an EN/TH retry message rather than
  leaving detection locked. Confirmation stays disabled without a valid pane.
- Escape invalidates the session and cancels its provider work. Late results
  cannot open a preview after cancellation.
- Added detector click/start/finish/timeout entries to the performance log.

## Verification

- `cargo test --locked`: 120 passed, zero failures.
- `cargo build --release --locked`: Windows x64 release build passed.
- RED: the new held-mouse native test failed against Alpha 4 because the
  overlay hid before button-up.
- GREEN: native-message `ScrollChecks` passed against Alpha 5: held-button
  selection, unchanged button pixels on pointer movement, duplicate-click
  handling, Escape, confirmation, manual scrolling, exact frozen-header/footer
  stitching, Stop/Cancel and PNG/clipboard parity.
- Fault injection delayed UIA by 12 seconds. The timeout smoke test passed two
  consecutive deadline/retry cycles, restored the overlay, kept invalid Start
  disabled and cancelled cleanly.
- Child-process tests verify actual stuck processes are reaped after timeout
  and cancellation, and dropping the Windows job terminates its child.

Final release smoke evidence: `artifacts/smoke-056d39f2db554fc583b8ad9fe3ff3dec`.
Executable SHA-256:
`7546BB11B46F9592A8A0C38C9F13FF8EA2699483C53E681A20402BA06D5B3FD1`.

These tests use native window messages, not physical mouse/keyboard delivery.
The fixture proves the native scrollbar fallback, not Lark UIA compatibility.
Actual Lark/Excel detection, physical Escape, OS wheel delivery, mixed-monitor
DPI and automatic capture require hands-on validation. No claim is made that
every Lark sheet exposes a usable scrollable pane.

## English Quick Check

Exit the old Rust preview from its tray icon, extract Alpha 5 into a new folder
and run its EXE. Open the affected Lark sheet, choose Scrolling, then click and
release inside the grid. Review the detected bounds before starting. If no pane
is found or the query times out, another click must work; Escape must cancel.
Test both automatic and manual modes. Report the visible status and latest
performance log if detection still fails. Do not overwrite the old folder.
