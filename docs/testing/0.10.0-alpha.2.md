# 0.10.0 Alpha 2: Audio Candidate

Date: 2026-10-15 (Asia/Bangkok). Local testing only; no commit/push or .NET edits.

## Scope

Four persisted audio modes in the Video menu: None (initial default), System
(all apps on the default playback endpoint), Microphone (default input), Both.
Windows WASAPI converts shared input to 48 kHz stereo PCM; Media Foundation
encodes AAC-LC at 192 kbit/s in the existing fragmented H.264 MP4.

Countdown and Save-after-Stop remain unchanged. Preparing an endpoint does not
start capture. Audio starts with the first captured video frame. Source loss
stops/finalizes the clip with a reason. Audio encoding failures preserve partial
media. Audio timeline buffers are bounded to one second per selected source.
Static/silent intervals receive timestamped silence instead of shortening audio.

Preview, clip copy, editing and device-selection controls are not added here.
Video editing remains outside the agreed scope.

## Native Checklist

1. Save existing work and Exit the prior Rust preview through its tray. Open
   this package and verify 0.10.0-alpha.2. Old settings start with No audio.
2. Video > No audio, then Video > Record screen/window. Record 15 seconds and
   verify countdown, Stop/Esc, Save afterwards and a silent playable MP4.
3. Select System audio (all apps). Play a non-private test sound and record it;
   verify video and sound, including silent intervals, stay in step.
4. Select Microphone. Speak during a short clip; verify the saved recording.
   Test a denied/unavailable input without changing Windows permissions: it must
   report a useful error, not silently record a different input.
5. Select Both and record test sound plus speech. Check both sources are present,
   with no clipping, speed change or growing offset. Both inputs use equal gain.
6. After each mode, verify Stop/Esc releases the input and Save occurs after
   recording ends. Cancel Save must show the retained clip's playable location.
7. If using a detachable test device, disconnect it mid-recording. The app must
   stop, retain accepted footage and show the input-loss reason.
8. Check EN/TH labels and selected menu marker; restart and verify the explicit
   choice persists. Recheck image capture, OCR and long capture after recording.
9. Longer recordings, mixed device rates/channels, USB/Bluetooth inputs,
   multi-monitor behavior and long-term synchronization remain separate gaps.

## Evidence

- Locked full suite: 257 passed, 0 failed, 0 ignored (2026-10-15).
- Formatting check passed; tracked changes have no whitespace errors.
- Locked optimized release build passed without warnings. PE is native, with
  no CLR header and no startup imports of mf.dll, mfplat.dll, mfreadwrite.dll or
  mmdevapi.dll. Media services remain loaded/activated on demand.
- Generated H.264/AAC footage reopened through the Windows decoder with stereo
  48 kHz PCM, expected tone energy and matching one-second duration. The silent
  MP4 regression also passed and rejects audio writes/has no audio track.
- Delayed audio does not stall initial video writes in the native muxer test.
- Timeline, mode settings and worker request compatibility tests passed.

Native microphone/loopback capture and the updated menu await user testing.
Synthetic encode/decode checks use generated PCM and pixels; they do not record
private windows, system playback or microphone input.
