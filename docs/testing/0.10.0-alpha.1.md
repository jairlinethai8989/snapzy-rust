# SnapZy Rust Preview 0.10.0-alpha.1

## Scope

This local candidate adds the first native video-recording stage. It records one
selected monitor or application window to a silent fragmented H.264 MP4 at a
target 30 fps, with a 3-2-1 countdown and no application duration limit.
The 2026-10-14 save-after-recording candidate starts without a file chooser.
Stop/Esc finalizes the clip first, then opens Save video. Cancelling the chooser
retains the completed clip under the instance's Recordings/Pending directory.

This stage intentionally excludes audio, pause/resume, region recording,
in-app playback, clip copy, an installer, .NET changes, commit and push.

## Automated verification

- Full locked suite: 248 passed, 0 failed, 0 ignored (2026-10-14).
- `cargo fmt --check` and `cargo build --locked --release` passed.
- Regression coverage confirms an empty Windows Graphics Capture frame pool
  may report `S_OK`; this is treated as “no frame yet,” not a capture failure.
  The earlier behavior could end recording after its first frame.
- Session countdown, preparation/finalization deadlines and unlimited recording state.
- Even-dimension padding, 32 MiB frame limit, timestamps and bitrate limits.
- Bounded JSON worker protocol and session isolation.
- Atomic no-overwrite publication, partial-file ownership and low-space policy.
- Same-volume saves move the existing clip without a second full-size file.
  Cross-volume export streams to a sibling staging file; only successful
  publication removes the original clip. File identity, Unicode names,
  destination collisions, missing/empty clips and failure retention are covered
  by real filesystem tests.
- Dynamically loaded Media Foundation creates a fragmented H.264 MP4.
- The synthetic MP4 is decoded again to verify frame count, dimensions,
  timestamps, changing pixels and top-to-bottom orientation.
- Windows Graphics Capture uses two frame-pool buffers, one CPU readback surface,
  source/PID lifetime checks and Direct3D device-loss detection.

## Native tester checklist

1. Close earlier Rust previews and unpack the candidate into a new folder.
2. Open SnapZy, choose **Video**, then **Record screen**. Select one monitor.
3. Verify countdown starts without a Save dialog. Record motion for at least
   15 seconds, then Stop. The Save video chooser must appear only after stopping.
4. Choose a new `.mp4` filename. Play the MP4 and verify correct orientation, full selected monitor, smooth
   motion, expected duration, no controller/launcher in the footage and no audio.
5. Repeat **Record screen**, then stop with Esc while another app has focus.
   Verify Save video appears after stopping, with no recording continuing behind it.
6. Choose **Record window**, select a moving test window, and verify only that
   window is recorded. Minimize or close it and verify recording stops safely.
7. During recording, verify capture/import/editor commands do not start. Open
   the tray menu and verify **Stop recording** works.
8. Start recording and choose Exit from the tray. Verify Cancel keeps recording;
   confirm Stop and Exit offers Save before normal project-exit checks. Cancel
   Save must keep the completed clip and cancel exiting.
9. Try choosing an existing filename and verify SnapZy refuses to overwrite it.
10. Verify English and Thai labels, controller sizing, display scaling and a
    recording longer than 30 minutes before considering the stage stable.
11. Stop another short recording and Cancel Save. Verify the retained path is
    shown, the clip there plays, and a new recording can start. An export failure
    must retain the original and must not overwrite an existing destination.

Additional global Esc, source-close behavior, controller exclusion and
long-duration recording checks remain pending unless individually recorded below.
