# SnapZy Rust Preview 0.3.0-alpha.2 Verification

Date: 2026-10-09, Asia/Bangkok. Local portable Windows x64 tester build only.
No push, tag or GitHub release. The .NET SnapZy and Neo Snap repos are unchanged.
Scope: the approved text-frame resize design; existing annotations are retained.

## Changes

- Select a text object to show six handles. Left/right middle handles change
  wrapping width without changing font size; four corners scale the font
  proportionally, anchored at the opposite corner.
- Text is rerasterized at its final font size, not stretched as a bitmap.
  Explicit newlines and the original editable Thai/English string are retained.
- One completed drag is one Undo step. Esc or capture loss cancels the draft.
  During dragging the frame is a lightweight preview; layout updates on release.
- Wrap width survives later text editing and numeric font-size changes.
  A long indivisible word may expand the frame rather than be truncated. Native
  Windows line-breaking behavior is used; custom Thai segmentation is not added.
- Resize cursors, translated tooltips, Help and layout-error messages are added.
  Double-clicking a resize handle does not accidentally open the text dialog.

## Limits

Fonts remain 8-128 source pixels; explicit wrap width is 24-32767 source pixels.
Native layout can expand to fit long words. Existing coordinate, glyph-mask
(1 MiB per document), history (64 steps) and source-pixel (32 MiB across windows)
limits remain. Rejected resize operations preserve the current document.
The source budget is not a bound on total process memory.

Blur is reversible visual obfuscation, not secure redaction. This build does not
add scrolling capture, OCR, recording, layers, merging, speech bubbles, shadows,
project saving or an installer. The next scrolling-capture document is a proposal,
not implemented functionality.

## Tester Checklist

1. Exit the previous Rust Preview through its tray menu. Extract this ZIP and
   run `SnapZy-Rust.exe`; no installer or .NET runtime is required.
2. Capture an area/window. Compare launch and capture responsiveness with the
   accepted 0.3.0-alpha.1. Check live drawing and window resizing for flicker.
3. Add multiline Thai/English using T. Switch to Select and click the text.
   Drag left/right middle handles: wrapping changes but font size stays the same.
   The frame moves during dragging and the text reflows when released.
4. Drag each corner: font size changes proportionally, without mirrored text.
   Test small/large sizes, long words, blank lines and text near the canvas edge.
   Reopen T and verify all input remains editable with original explicit newlines.
5. Test Undo/Redo once per drag; Esc during a drag must leave the text unchanged.
   Double-click a handle should resize, not open text entry. Double-click inside
   the text should still edit it. Test movement, crop and numeric font-size edits.
6. Copy to an actual chat app and save PNG; compare original pixel dimensions and
   final text with the editor. Export must not include selection handles.
7. Recheck shapes, pen, numbers, blur, color, deletion and separate editors.
   Switch EN/TH; inspect Help and tooltips. Test physical Thai IME and 125%, 150%,
   200% scaling, including mixed-DPI monitors, before release approval.

Report tool, image dimensions, display scaling, steps and whether a failure
occurs during dragging, on release, on Copy or in the saved PNG.
