Date: 2026-10-12. Local candidate only; native integration verification incomplete.
Rust only. No .NET edits, commit, push, installer or public release.

## Scope

- Native top-level editor hosts with independent per-document child editors.
- Persistent New tab default / New window alternative, EN/TH launcher labels.
- Captured destination and origin identities for capture, file opening and combine.
- Native tab overflow, labels, close targets and Ctrl+Tab / Ctrl+Shift+Tab / Ctrl+W.
- Host-scoped and app-scoped transactional closing; saves precede any removal.
- Host-owned dialogs and OCR result windows with document-owned data routing.
- Standalone PNG/JPEG/BMP opening as a new independent, unsaved editable work.
- Same schema 2, image/source budgets and sixteen-document global limit.

### Open UI Finding: Preview Status Clipping

The post-save `Project saved` status visibly wrapped and its second line was
clipped in the default-sized editor. The status layout in `src/ui.rs` places the
control at logical x=394, width=`(logical_width - 720).max(10)`, height=28; at an
800 px client width this leaves 80 px. The preview creates it as a plain STATIC
control with style 0, permitting wrapping. The completion callback publishes
`Project saved` from `src/project_ui.rs`. This explains the observed clipping.

This cosmetic finding is recorded, not fixed or re-tested. Keep it visible for
the scoped UI cleanup; no data-loss or persistence failure was observed in the
executed cases. No production code changes, .NET edits, commit or push.
