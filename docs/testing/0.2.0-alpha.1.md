# SnapZy Rust Preview 0.2.0-alpha.1 Verification

Date: 2026-10-09, Asia/Bangkok. Local tester candidate, not a public release.

## Scope

Only snapzy-rust is changed. The .NET SnapZy and Neo Snap repositories,
installations and settings are not changed. No implementation push, tag or
GitHub release is authorized until the tester approves this candidate.

## Automated Checks

- Rust 1.99.0, x86_64-pc-windows-msvc, Windows 11 build 26100.
- `cargo test --locked`: 23 passed, zero failed.
- `cargo fmt --all --check`: passed.
- `cargo build --release --locked`: passed.
- `git diff --check`: passed for tracked changes.
- Clippy passed with warnings denied except these four style lint categories:
  `chunks_exact_to_as_chunks`, `collapsible_if`, `let_and_return`,
  `manual_dangling_ptr`. This is not an unqualified strict-Clippy pass.

The tests exercise document/history isolation, no-op gestures, crop restoration,
hit testing, movement, styling, redo branching, export revisions, original pixel
preservation, antialiased annotation rendering, PNG and flattened clipboard DIB.
The clipboard regression requires a positive-height, bottom-up Windows DIB.

## Native Checks

`tools/smoke-test.ps1 -EditorChecks` checks real native windows using its own
synthetic image fixture and isolated settings directory. It covers:

- Launcher EN/TH, region/window/desktop capture, Escape and repeated input.
- PNG dimensions and pixels, Unicode filename, hotkey conflict/success and exit.
- Pen, line, arrow, rectangle, select/move/delete, color/width, Undo/Redo.
- Pending crop, confirmation/cancellation, cropped PNG and crop restoration.
- Editor EN/TH, all 15 tooltip registrations and Help dialog opening/closing.
- Toolbar survival after repaint, screenshots and compact control bounds.
- Windows Forms clipboard image retrieval with composed dimensions/pixels.

Both connected monitors are 96 DPI. Mixed/high-DPI behavior is not verified.
Screenshots are synthetic editor fixtures, not private desktop captures.
Chat-app paste behavior, physical hotkey delivery, tray use and unsaved-window
prompts still need hands-on tester confirmation.

## Performance Comparison

Five alternating samples per build on the same PC, using identical native smoke
fixtures without editor gestures. Baseline: accepted Rust 0.1.0-alpha.1, not .NET.
No builds or lint commands ran concurrently with this final comparison.

| Metric | Baseline Median / Slowest | Candidate Median / Slowest |
| --- | --- | --- |
| Launcher window detected (ms) | 241.51 / 284.89 | 243.61 / 328.08 |
| Selection window detected (ms) | 158.93 / 187.61 | 153.64 / 180.63 |
| Preview window detected (ms) | 47.58 / 65.47 | 44.70 / 57.60 |
| Instrumented launcher ready (ms) | 45.226 / 63.570 | 47.067 / 59.282 |
| Instrumented selection first paint (ms) | 174.689 / 186.051 | 172.460 / 263.087 |
| Instrumented preview first paint (ms) | 68.353 / 88.952 | 113.544 / 125.171 |
| Peak working set (bytes) | 93306880 / 104480768 | 101330944 / 104108032 |

First-paint timing is application WM_PAINT completion, not compositor-visible
screen completion. Launcher-ready timing excludes earlier process startup;
window-detection timing includes process startup/polling. These are different
metrics and are not language-level performance claims or latency guarantees.

Preview first paint has a repeatable extra cost of about 45 ms in this final run.
Instrumentation locates initialization cost in the additional native controls,
tooltip creation and layout, not source-image composition. A representative
candidate capture recorded 48.239 ms creating controls, 4.341 ms for tooltips,
8.856 ms for layout and 0.001 ms composing the unedited shared source. Stage
spans are diagnostic, not additive measurements of compositor presentation.
The candidate is responsive in the automated fixture but must still be judged
by the tester; do not claim zero performance regression.

Reproduce with `tools/compare-preview.ps1 -Samples 5` after preserving baseline.

## Tester Checklist

1. Close an older Rust Preview through its tray menu, then extract the ZIP and
   run `SnapZy-Rust.exe`. No .NET installation or setup is required.
2. Compare launcher/capture response against the accepted Rust alpha.1.
3. Draw all four annotation types. Verify initial red color and 5 px width.
4. Select/move an object, change color/width, delete it, Undo and Redo.
5. Crop, confirm with Enter, Undo it and cancel another crop with Escape.
6. Copy into the chat app you use; save PNG and inspect native dimensions.
7. Switch EN/TH, open Help, resize the editor and check another monitor/DPI.
8. Check hotkeys, tray restore and discard confirmation before closing.

Deferred tools include text, numbered steps, blur, callouts, layers, multiple
images, project saving, OCR, scrolling capture and video. The candidate has no
installer or startup registration and is not a replacement for the .NET apps.
