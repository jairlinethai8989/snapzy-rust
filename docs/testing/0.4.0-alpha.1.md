# SnapZy Rust Preview 0.4.0-alpha.1 Verification

Date: 2026-10-09, Asia/Bangkok. Local portable Windows x64 tester only.
No push, tag, installer or GitHub release. The .NET repositories are unchanged.
Scope: approved manual vertical scrolling pilot. Text backgrounds and speech
bubbles have conceptual approval but await review of their written design;
they are not implemented in this increment.

## Changes

- Scrolling selects a fixed region inside one application. A compact controller
  stays outside that region. Scroll the target downward manually, then Stop to
  edit the accepted image or Cancel to discard the session.
- Pixel matching excludes stationary rows, rejects ambiguous shifts and retains
  bounded footer lookbehind. Frozen headers and detected light footer/scrollbar
  bands are kept once, without resampling the original pixels.
- Capture and matching run off the UI thread with a one-event bounded channel.
  Per-session ownership prevents a cancelled worker from opening a late editor.
  A new capture command cancels the active scrolling session.
- Target geometry/DPI changes, minimization, detected covering windows and an
  overlapping controller pause acceptance. Full-frame stability requires at
  least 200 ms; continuous changes report a paused status after three seconds.
- Stop returns only accepted pixels. No confirmed movement is explicitly
  reported as a single screenshot. Memory limits stop with a partial-result
  notice. There is no silent quality reduction or unlimited-length claim.

## Limits

Manual downward vertical movement only; keep overlap and pause between steps.
Automatic wheel input is not included. Whole-monitor regions may leave no room
for the controller and are rejected; select a smaller target region. Full-frame
animation can prevent any stable image from being accepted. Occlusion checks use
the existing titled-window enumeration and are not a guarantee against every
overlay, protected surface or untitled window. Footer detection examines at most
the bottom 160 px or one third of the viewport, whichever is smaller.

Aggregate source capacity remains 32 MiB across editor windows, with bounded
retained strips/lookbehind and a maximum output height of 32767 px. At width
1920, 32 MiB permits at most about 4369 rows before other sources and lookbehind;
actual length is lower. This is not a bound on total process working memory.
No disk-backed capture, OCR, video, layers, image merging, project saving,
callouts, text backgrounds or installer is added in this build.

## Tester Checklist

1. Save any old editor work, exit Rust Preview through its tray menu, extract
   the new ZIP and run `SnapZy-Rust.exe`. No installer or .NET is required.
2. Recheck opening, Area, Window and Desktop captures against 0.3.0-alpha.2.
   Report repeated delays, not just the best run. Recheck live drawing/resize.
3. Open each previously good/problematic Lark sheet. Choose Scrolling and select
   the visible table including its frozen header/footer, leaving space outside
   the selected region for the controller. Start with a modest region/length.
4. Scroll downward in small overlapping steps, pause until Capturing and the
   accepted height updates, then scroll again. Stop and inspect every join for
   missing/duplicated rows or repeated horizontal bars. Repeat the same sheet
   several times to look for the intermittent problem. Also try Excel/web pages.
5. If Paused appears, restore the target position or the last overlapping view.
   Try reverse/horizontal movement, animation and covering/minimizing the target.
   Invalid frames must not be appended. Stop may return a valid partial image.
6. Cancel mid-session, immediately start another capture and verify no old image
   opens later. Stop without scrolling should report a single screenshot.
7. Compare saved PNG and clipboard in an actual chat app with the editor at
   original pixel size. Test 125%, 150%, 200% and mixed-monitor DPI separately.
8. Text/speech-bubble backgrounds are not available in this build; review
   `../superpowers/specs/2026-10-09-text-background-callout-design.md` separately.

Report build, application/sheet, selected pixel dimensions, display scaling,
accepted height, controller status and exact steps. Share only non-sensitive
images; synthetic table success does not certify authenticated Lark content.
