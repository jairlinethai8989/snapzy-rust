# SnapZy Rust Preview 0.9.0-alpha.8

Date: 2026-10-11 (Asia/Bangkok). Local portable test candidate only.
No Git push, public release or .NET product changes.

## Highlighter

- Native Highlighter immediately after Pen; EN/TH accessible label, tooltip and Help.
- Independent yellow `#FFF258`, 24 source-pixel width and 40% opacity defaults.
  Normal annotation defaults remain red and 5 px.
- Contextual opacity (0-100%) and existing width (1-40 px) and color controls.
- Multiply blending preserves black text. One continuous object blends once
  across self-overlap; separate highlight objects darken overlapping areas.
- Select/move, recolor/resize, opacity edits, ordering, Delete and Undo/Redo.
  Click-only gestures do not create marks; Esc cancels an unfinished mark.
- Shared live/final blending, bounded live tiles and immutable source pixels.
  Final work remains on the existing composition worker with revision/export guards.

## Tester Steps (English)

1. Save old work and exit the old Rust preview via Tray. Extract Alpha 8 into a
   new folder, run `SnapZy-Rust.exe`, and verify version `0.9.0-alpha.8`.
2. Capture black text; choose Highlighter and drag across it. Check yellow/24/40
   defaults, readable text, smooth feedback and no color jump on release.
3. Change color, width and opacity (0, 40, 100). Select and move/delete the mark;
   Undo/Redo changes and draw another mark after undoing opacity.
4. Switch Pen/Highlighter and confirm each retains its settings independently.
   Mix image/text/blur layers and reorder. PNG and clipboard must match.
5. Check EN/TH, a compact window, 125-200% or mixed-DPI monitors, real chat paste,
   Lark automatic/manual scrolling and physical Esc-to-Stop again.

## Final Scrolling Verification

An earlier final-binary scrolling rerun confirmed two blocked detector helpers were
reaped, labeled fallback/retry worked and detection cancellation succeeded.
The run then failed the foreground-handoff assertion again: Chrome was current
instead of the test-owned source. No source wheel was deliberately sent to
Chrome, and the test's safety assertion was not bypassed. The cause of that
handoff failure was not conclusively established. The Highlighter increment
did not edit the scrolling backend or relax its timing/focus checks.

Evidence: `artifacts/smoke-20a59f642c504964bbbafa4f9f6ace4a/partial-results.json`.
This is explicitly a failed/incomplete run, not a passing scrolling result.

After the user confirmed an input-free window, the final binary passed the
full scrolling fixture without MessageOnly:
`artifacts/smoke-ea0d468504c749d4bce3e6b7025a5a56/results.json`.
Version and SHA-256 match the staged executable above. Manual wheel handoff,
automatic scrolling with a 900 ms delayed source, exact frozen-header/footer
PNG pixels, PNG/clipboard parity, Pause/Resume, focus/cover pauses, no-motion
completion, partial Stop, Cancel/no late input and detector timeout recovery
passed. Guarded OS-injected Escape stopped capture and preserved accepted
pixels, including when another owner reserved the hotkey. Registration was
released after stopping. No safety guard was bypassed.

This uses test-owned windows, guarded OS clicks/Escape and product-targeted
wheel messages. It is not live Lark, a physical-key test or an OS wheel probe.
Observer launcher/selection/preview timings were 352.63/170.73/48.71 ms;
peak working set was 107,487,232 bytes. No test-owned app process remained
after completion. Real Lark and physical Esc acceptance remain tester checks.
